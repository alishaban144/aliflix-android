# Mobile audio subtitle sync (v3.1.133)

One tap under Audio & subtitles / SUBTITLE SYNC uses the active Media3 sink. A forwarding sink preserves the original audio configuration and reads a duplicate decoded PCM buffer. It creates no player, stream request, microphone recording, executable, transcription or paid API call. PTS minus Media3 stream offset is the original media clock, independent of playback speed. Sink retries are deduplicated; seek/format/source changes invalidate analysis.

The Kotlin VAD uses downsampled speech-band energy, zero crossings, adaptive noise floor and short hangover. At most six minutes of 50 Hz timestamped speech decisions (~162 KiB) are retained. Raw PCM is never persisted or uploaded. Analysis runs on Dispatchers.Default, initially using two or three non-overlapping 25-second speech-rich windows and collecting up to six naturally. Missing audio, discontinuities, music-heavy windows, competing peaks, inconsistent scenes and unsupported fits are rejected. A four-minute timeout and explicit Cancel/Reset end collection. FFT memory is bounded to the +/-120-second offset search.

FFsubsync's MIT speech-activity/FFT idea is adapted to normalized correlation over observed windows only. Supported drift candidates are known 24/25/23.976 frame-rate conversions; a non-unit rate needs a baseline of at least 120 seconds and two seconds of measurable accumulated drift. Subtle drift that cannot be established by the available baseline remains unsupported. Every scene must support the same match, with offset and rate ambiguity gates. This is conservative timing inference, not guaranteed alignment on arbitrary soundtracks.

Original downloaded/account/offline cues stay intact. Automatic rate/offset is applied once to originals, then manual delay is added. Reset clears both and saves a tombstone. Caption timelines update without replacing the media item, preparing, seeking, changing audio or restarting playback. Corrected VTT remains available for Cast handoff. Remote Cast exposes no local decoded PCM, so new analysis is disabled while casting; existing corrections survive handoff. Embedded tracks without a complete loaded timeline cannot be analysed; loaded subtitle files are supported.

Cache keys hash exact episode/content identity, full source URI including query, MIME type, source/rendition rules, offline identity, selected audio format/duration and original subtitle payload. Different signed URIs intentionally miss. Only digests and numeric corrections sync through account-scoped Firebase player state. Compare-and-set transactions use the last confirmed cloud revision, reject stale overwrites and protect Reset. Pending corrections survive restarts and retry offline failures. Existing player preference scopes isolate users.

Picked for you starts during the launch overlay and reacts to Firebase-restored Likes, playback progress and history. Up to six taste anchors supply cached TMDB recommendation neighborhoods. Votes/rating floors and shared specific genres/keywords/creators gate popularity ranking; there is no unrelated editorial fallback or AI call. Empty history yields no personalized rail. Cloudflare migrates once on mobile upgrade, then user selections remain selectable. My List/Favorites genre tabs retain the All grid state and fade between filters. App Updates sits below Account; Play Next Episode controls the existing automatic-next countdown and syncs as a player preference.

Focused JVM checks cover FFT equivalence, both offset signs, translation independence, supported drift, silence/ambiguity/scene conflicts, immutable originals/manual delay, source/subtitle/audio fingerprints, passive PCM capture and recommendation relevance. Emulator/device/live API checks and TV builds are explicitly waived. These checks do not establish real-device visuals, Cast receiver behavior, Firebase round trips or arbitrary soundtrack accuracy.
