# Mobile audio subtitle sync (v3.1.134)

One tap under Audio & subtitles / SUBTITLE SYNC uses the active Media3 sink. A forwarding sink reads a duplicate decoded PCM buffer. Its format support selects the existing platform decoder at local playback preparation, avoiding encoded passthrough/offload when a platform decoder exists. Passthrough-only formats on devices without a decoder retain working audio and report analysis unavailable instead of changing their playback. A Sync tap never switches or restarts the audio pipeline. It creates no player, stream request, microphone recording, executable, transcription or paid API call. PTS minus Media3 stream offset is the original media clock, independent of playback speed. Sink retries are deduplicated; source/audio changes cancel analysis; seeks and sink flushes collect fresh evidence safely.

A pinned 153 KB Android WebRTC VAD AAR uses the same six-band Gaussian-mixture detector family as FFsubsync. A streaming box-filter resampler produces exact 8 kHz/20 ms frames across codec-sized buffers, including 44.1 kHz stereo and centre-channel surround dialogue. At most six minutes of 50 Hz timestamped speech decisions (~162 KiB) are retained. Raw PCM is never persisted or uploaded. Analysis runs on Dispatchers.Default, using two or three non-overlapping 10-second speech-rich windows initially. The rolling buffer starts at playback, before a tap. Up to six distributed samples continually refresh with new dialogue after an inconclusive match, including distant anchors for drift. Snapshots and FFT work happen outside the playback lock; samples beyond the current player position are excluded. Missing audio, discontinuities, music-heavy windows, competing peaks, inconsistent scenes and unsupported fits are rejected. Four minutes of actively playing collection, a ten-minute wall limit, or explicit Cancel/Reset end collection. Paused playback shows a resume hint; Failed shows a working Retry, without changing availability or deleting existing corrections. JNI/capture errors never escape into the playback renderer. FFT memory is bounded to the +/-120-second offset search.

FFsubsync's MIT speech-activity/FFT idea is adapted to normalized correlation over observed windows only. Supported drift candidates are known 24/25/23.976 frame-rate conversions; a non-unit rate needs a baseline of at least 120 seconds and two seconds of measurable accumulated drift. Subtle drift that cannot be established by the available baseline remains unsupported. Initially every scene must support the same match. Once four or more samples exist, one weak outlier may be removed only with at least three independent agreeing scenes. A strong contradictory scene remains a rejection. Offset and rate ambiguity gates remain enforced. This is conservative timing inference, not guaranteed alignment on arbitrary soundtracks.

Original downloaded/account/offline cues stay intact. Automatic rate/offset is applied once to originals, then manual delay is added. Reset clears both and saves a tombstone. Caption timelines update without replacing the media item, preparing, seeking, changing audio or restarting playback. Corrected VTT remains available for Cast handoff. Remote Cast exposes no local decoded PCM, so new analysis is disabled while casting; existing corrections survive handoff. Embedded tracks without a complete loaded timeline cannot be analysed; loaded subtitle files are supported.

Cache keys hash exact episode/content identity, full source URI including query, MIME type, source/rendition rules, offline identity, selected audio track/format and original subtitle payload. Different signed URIs intentionally miss. Stream duration is deliberately excluded from track identity because HLS timelines change while loading. The v2 algorithm namespace prevents reuse of previous heuristic fits. Only digests and numeric corrections sync through account-scoped Firebase player state. Compare-and-set transactions use the last confirmed cloud revision, reject stale overwrites and protect Reset. Pending corrections survive restarts and retry offline failures. Existing player preference scopes isolate users.

Picked for you starts during the launch overlay and reacts to Firebase-restored Likes, playback progress and history. Up to six taste anchors supply cached TMDB recommendation neighborhoods. Votes/rating floors and shared specific genres/keywords/creators gate popularity ranking; there is no unrelated editorial fallback or AI call. Empty history yields no personalized rail. Cloudflare migrates once on mobile upgrade, then user selections remain selectable. My List uses only each title's first/main genre, in the same count-sorted groups as the original shelves. Its violet capsule indicator glides between tabs; content fades/slides while retaining each genre's scroll position. Favorites uses the original grouped grid, without tabs. TV uses the unchanged grouped layout. App Updates sits below Account; Play Next Episode controls the existing automatic-next countdown and syncs as a player preference.

Focused JVM checks cover FFT equivalence, both offset signs, translation independence, supported drift, silence/ambiguity/scene conflicts, immutable originals/manual delay, source/subtitle/audio fingerprints, passive PCM capture, real codec-sized 44.1 kHz buffers, partial sink-write retries, refreshing sample evidence, fail-safe capture errors, and padded subtitle cues with VAD dropouts. Emulator/device/live API checks and TV builds are explicitly waived. These checks do not establish real-device visuals, Cast receiver behavior, Firebase round trips or arbitrary soundtrack accuracy.

MIT notices are packaged in `app/src/mobile/assets/audio-sync-notices.txt`.
