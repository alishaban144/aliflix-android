# Mobile audio subtitle sync (v3.1.135)

One tap under Audio & subtitles / SUBTITLE SYNC uses the active Media3 sink. A forwarding sink reads a duplicate decoded PCM buffer. Its format support selects the existing platform decoder at local playback preparation, avoiding encoded passthrough/offload when a platform decoder exists. Passthrough-only formats on devices without a decoder retain working audio and report analysis unavailable instead of changing their playback. A Sync tap never switches or restarts the audio pipeline. It creates no player, stream request, microphone recording, executable, transcription or paid API call. PTS minus Media3 stream offset is the original media clock, independent of playback speed. Sink retries are deduplicated; source/audio changes cancel analysis; seeks and sink flushes collect fresh evidence safely.

A pinned 153 KB Android WebRTC VAD AAR uses the same six-band Gaussian-mixture detector family as FFsubsync. A streaming box-filter resampler produces exact 8 kHz/20 ms frames across codec-sized buffers, including 44.1 kHz stereo and centre-channel surround dialogue. Aggressive mode 2 retains quieter dialogue better than the previous mode 3. At most thirty seconds of 50 Hz timestamped speech decisions (~13.5 KiB) are retained. Raw PCM is never persisted or uploaded. The rolling buffer starts at playback, before a tap. Tap during dialogue to use one contiguous 6-12 second window ending at the tap position; neither older scenes nor decoded audio ahead of playback are selected. A recently voiced final second is required. There is no collection stage, wait for future audio, resampling of other scenes or retry loop. Analysis runs once on Dispatchers.Default, with a two-second processing deadline and cooperative FFT cancellation. The state goes directly to Syncing, then Synced or Failed with an enabled Retry. Missing/short audio, discontinuities, stale evidence, competing peaks and uninformative continuous speech are rejected promptly, preserving existing corrections. Snapshots and FFT work happen outside the playback lock; JNI/capture errors never escape into the renderer. FFT memory is bounded to the +/-120-second offset search.

FFsubsync's MIT speech-activity/FFT idea is adapted to normalized correlation over the current window only. A short smoothing filter tolerates isolated VAD dropouts. The whole +/-120-second subtitle neighborhood is searched without a nearest-line bias. A strong unique peak and a narrow offset plateau are required; silence, repetitive timing and continuous speech cannot identify a reliable offset. This action estimates only a constant offset, retaining any previously validated cached timing rate. The immediate single-exchange interaction replaces the earlier multi-scene drift collector: a short exchange cannot establish new timing drift. This is language-independent speech timing inference, not speech recognition or guaranteed alignment on arbitrary soundtracks.

Original downloaded/account/offline cues stay intact. Matching includes the existing manual delay and cached rate, then solves a new automatic offset against originals; existing automatic offsets never feed back into matching. Manual settings are preserved. Automatic rate/offset is applied once to originals, then manual delay is added. Reset clears both and saves a tombstone. A source/audio/subtitle change, seek, Cancel, Reset or activity stop cancels or invalidates the attempt. A concurrent account correction or Reset wins over its result. Caption timelines update without replacing the media item, preparing, seeking, changing audio or restarting playback. Corrected VTT remains available for Cast handoff. Remote Cast exposes no local decoded PCM, so new analysis is disabled while casting; existing corrections survive handoff. Embedded tracks without a complete loaded timeline cannot be analysed; loaded subtitle files are supported.

Cache keys hash exact episode/content identity, full source URI including query, MIME type, source/rendition rules, offline identity, selected audio track/format and original subtitle payload. Different signed URIs intentionally miss. Stream duration is deliberately excluded from track identity because HLS timelines change while loading. The v2 algorithm namespace prevents reuse of previous heuristic fits. Only digests and numeric corrections sync through account-scoped Firebase player state. Compare-and-set transactions use the last confirmed cloud revision, reject stale overwrites and protect Reset. Pending corrections survive restarts and retry offline failures. Existing player preference scopes isolate users.

Picked for you starts during the launch overlay and reacts to Firebase-restored Likes, playback progress and history. Up to six taste anchors supply cached TMDB recommendation neighborhoods. Votes/rating floors and shared specific genres/keywords/creators gate popularity ranking; there is no unrelated editorial fallback or AI call. Empty history yields no personalized rail. Cloudflare migrates once on mobile upgrade, then user selections remain selectable. My List uses only each title's first/main genre, in the same count-sorted groups as the original shelves. Its violet capsule indicator glides between tabs; content fades/slides while retaining each genre's scroll position. Favorites uses the original grouped grid, without tabs. TV uses the unchanged grouped layout. App Updates sits below Account; Play Next Episode controls the existing automatic-next countdown and syncs as a player preference.

Fourteen focused JVM checks cover FFT equivalence, both offset signs from one current exchange, translation independence, retaining a known rate, silence/ambiguity, cooperative cancellation, immutable originals/manual delay, source/subtitle/audio fingerprints, passive PCM capture, codec-sized 44.1 kHz buffers, partial sink-write retries, excluding old/future/discontinuous samples, fail-safe capture errors, and padded subtitle cues with VAD dropouts. Emulator/device/live API checks and TV builds are explicitly waived. These checks do not establish real-device visuals, Cast receiver behavior, Firebase round trips or arbitrary soundtrack accuracy.

MIT notices are packaged in `app/src/mobile/assets/audio-sync-notices.txt`.
