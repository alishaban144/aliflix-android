# Aliflix v3.1.113

Mobile version code 203; based on v3.1.112. TV stays on 3.1.69.

## CineJoy playback

CineJoy did fetch, but the app threw the result away. The resolver only accepted a stream once the
embedded web player was actually playing, and CineJoy is a client-rendered single-page app that
does not autoplay without a user gesture, so no progress message was ever sent. Every CineJoy
attempt burned its 10-second budget and silently fell through to the next source, which looked
exactly like a source that does not work.

- The HLS manifest is now reported the instant the provider exposes it, before and independently of
  any playback state. The native player only needs the URL, the referer, and the cookies.
- A direct progressive source is watched as well, for players that never request a manifest.
- CineJoy's watch route loads directly instead of inside a wrapper iframe, removing a frame hop
  and an origin boundary from the discovery path.
- The CineJoy resolve budget is 30 seconds instead of 10, which covers its bundle boot plus its own
  API round trip. Every other provider keeps its existing 10-second budget.
- A main-frame probe recovers the manifest directly when the WebMessage bridge is unavailable on a
  given WebView, so a playable stream is never discarded.
- A stream-only report no longer updates resume points or duration; it only records the stream.

Measured against the live site in a real Chromium with the app's own injected script and no
autoplay override: the manifest is reported after 1.6 s for a movie and 1.7 s for a series episode.

## Artwork backdrop

Home and the movie/series page share the layered treatment used by the reference site: an
oversized, defocused copy of the same artwork glows behind the sharp crop, a long bottom-up scrim
dissolves both into the page background, and soft top and side falloffs keep the status bar and
edges calm. The scrim uses many closely spaced stops, which is what removes the visible seam
between poster and page. Everything is drawn slightly darker than the reference so white titles
and body copy keep their contrast. `Modifier.blur` is a no-op before API 31, so those devices keep
the oversized low-opacity copy, which still softens the plane.

Validation: mobile and TV Kotlin compilation, plus live browser verification of stream discovery
against cinejoy.pk. Emulator and device validation were waived, so on-device playback and the
rendered backdrop remain unverified.
