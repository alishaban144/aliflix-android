# Aliflix v3.1.115

Posters on the main screen and on the movie and series page are no longer cropped or washed out,
and the dark translucency now applies only to the content below the poster.

## The poster was being cropped to the whole screen

The artwork behind the hero was drawn with `matchParentSize()` and `ContentScale.Crop` across the
entire screen, and the hero height was used only to decide where a gradient should be painted on
top of it. The poster itself was never framed by the hero at all.

That is what broke it. TMDB backdrops are 16:9 and posters are 2:3, while a phone plane is roughly
9:19.5. Cropping a 16:9 image to fill a full-height phone keeps only a narrow vertical slice in the
middle of the frame, so the composition the artwork was drawn for is cut away on both sides and the
subject is zoomed far past the point where it reads as a picture. The same crop was applied on the
details screen, where the hero occupies about half the height, so the artwork was being blown up
roughly twice as far as it needed to be.

The poster is now drawn into a band that is exactly as tall as the hero, and cropped to that band
instead of to the screen. The gradient that darkens the page is a separate element positioned
below the band, so the two meet on the poster's lower edge rather than being painted over the
artwork. The defocused copy behind it still softens the plane and now shows through the gradient
below the poster as a glow, rather than competing with the sharp crop as a second picture.

## The details screen measured the boundary from the wrong origin

The details hero sits inside a list that is padded down by the status bar, so the hero's top edge is
one status bar below the top of the screen. The backdrop measured the ramp's start from the top of
the screen, which put the beginning of the gradient roughly a status bar height *above* the actual
bottom of the poster. The result was a dark band lying across the lower part of the artwork, and a
visible seam where the gradient met the hero.

The band now takes a top inset, and the details screen passes the same
`statusBarsIgnoringVisibility` padding that positions its own hero. Poster and gradient therefore
start and end on the same line, and the band is clamped to the plane on both edges so an inset or a
hero larger than the screen can never invert it or draw outside it.

The main screen needs no inset: its hero is the first item in a list that begins at the very top,
with the header overlaid on top of it rather than padding it. It continues to use the shared
`homeHeroHeight` helper, so the banner and the boundary cannot drift apart at larger font scales.

## Posters in the rails

The "More Like This" rail on the details screen still carried a `Color.Black.copy(alpha = 0.42f)`
gradient over the full height of each poster, which is the wash v3.1.114 had already removed from the
home cards but missed here. It is removed too. Every badge in that rail already carries its own
opaque backing, so the rating, the year and the rank stay readable without it.

## Validation

The mobile unit test suite and `lintMobileDebug` pass. Five new tests cover the band geometry
directly: the band matches the hero height, a status bar inset moves the whole band and leaves the
ramp below it, a hero taller than the plane is cut off without inverting, an inset past the plane
collapses to an empty band, and an unbounded or empty plane yields an empty band. Mobile and TV
Kotlin compilation pass with no new warnings.

Emulator validation ran and reported five failures, all pre-existing and in areas this release does
not touch: `WebStreamHandoffTest.actualIframeVideoAndBlobManifestCanBeHandedToNativePlayback`,
`ExactProgressTest.durableProgressRejectsBootstrapAndStaleSamplesAndRetainsEpisodeIdentity`,
`PhonePlayerPolishTest.pinchChangesFitWithoutWaitingForOneLargeFrame`,
`PhonePlayerPolishTest.firstLibrarySwipeExpandsViewportWithoutFlingingToTheBottom` and
`DiscoverCatalogueUiTest.catalogueAndPeopleRemainAvailableWithoutAskAliflix`. The home screen test
that renders the changed hero, `PhonePlayerPolishTest.homeDissolveKeepsItsFrameAndPlayTargetsTheVisibleTitle`,
passed, as did the other fourteen device tests. These same five are waived on every release branch
through v3.1.114, so the release proceeds with device validation waived as on those releases. The
rendered result on a device is therefore only partly verified: the changed home hero is covered, the
details hero is not.
