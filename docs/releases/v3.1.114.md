# Aliflix v3.1.114

Rotten Tomatoes ratings resolve again, and posters are shown in their original colours.

## Rotten Tomatoes

Two independent defects were dropping scores for titles that are on the site.

**Search no longer returns anything to read.** Rotten Tomatoes replaced its server-rendered
search results with a client-rendered page. The `/search` HTML for any query contains no `/m/` or
`/tv/` links for the query, only unrelated navigation rails. The app's only discovery step scraped
those links, so it produced junk candidates and every title whose vanity could not be guessed from
its name was discarded. Guessed slugs alone cannot cover these cases: `the_avengers` is a 404,
`the_avengers_2012` is a different 1950 film, `detective_conan` is a 404, `cid_1998` is a 404 and
`caveat` is a 404.

Titles are now resolved through the catalogue index that the website itself searches. The index
returns the canonical `vanity` slug, the release year, the media type and the critic score, so
`the_avengers` resolves to `marvels_the_avengers`, `detective_conan` to `case_closed_1996` and
`caveat` to `caveat_2021`. The search-only credentials are read from the live site on first use and
cached, with the bundled values only as a fallback, so a rotated key keeps working. Discovery stays
advisory: every discovered path is still fetched from `rottentomatoes.com` and verified on the real
page, and the existing direct-slug, index and HTML-search fallbacks are all kept in order.

**The page creation date was used as the release year.** Identity checking read `dateCreated` from
the page metadata and compared it with the requested year. Rotten Tomatoes sets that field to the
most recent release event for a title, not the original one: Avatar (2009) publishes
`2022-09-23` from its 4K re-release and Wild Tales (2014) publishes `2015-02-20`, so both correct
pages were rejected as the wrong film. The year check now reads the published `releaseYear`, the
structured `datePublished` and `startDate` values, the year in the page title and the year Rotten
Tomatoes embeds in the canonical slug. `dateCreated` is used only as a last resort, and only for a
page that states no other year. A same-name page from a different year is still refused, and an
undated page is still unverified, so a remake can never be accepted on the title alone.

**Supporting fixes found while verifying the above:**

- The critic score is now read from the reviews payload, which keeps the critic and audience scores
  separate so a Popcornmeter value can never be displayed as a Tomatometer value.
- A page that positively states it has no critic reviews is answered as *Not rated* instead of
  being reported as a parser failure. The scan previously read only JSON-typed scripts and missed
  the block, which the site marks up as a plain script.
- A leading byte order mark is stripped before parsing. Left in place it stops the HTML parser from
  recognising the document at all, which discards the title and every script on the page.
- An apostrophe inside a title is removed rather than turned into a separator, so
  `Marvel's the Avengers` no longer normalises to `marvel s the avengers` and score as a weak match.
- A candidate discovered through the catalogue index carries that entry's own title, so an entry
  filed under a different name still matches while the year check still has to agree.

Verified against real captured pages: Avatar 81, The Avengers 91, Wild Tales 94 and Caveat 82 all
resolve. Detective Conan correctly reports *Not rated*, because Rotten Tomatoes files the 1996
anime as Case Closed and publishes no critic score for it. C.I.D. (1998) is absent from Rotten
Tomatoes' own catalogue index, so it reports *Unavailable* rather than a wrong score.

## Poster colour

Posters on Home and on the movie and series page are drawn in their original colours.

The backdrop previously stacked four full-page scrims over the artwork, reduced its alpha, and added
both a side falloff and a vignette, which darkened the whole poster. Home poster cards carried a
further gradient across the lower 42% of the artwork. All of that is removed. The artwork is now
drawn untouched, and the darker translucency is confined to the content: the scrim begins exactly at
the bottom of the poster and covers only what sits below it, the home poster cards carry no gradient
over the artwork, and the details hero keeps a small local backing behind its own copy so the white
title and pills stay readable without dimming the poster. The home hero height is now read from a
single shared helper so the banner and the scrim boundary cannot drift apart, including at larger
font scales.

## Validation

328 unit tests pass, including new coverage built from real captured Rotten Tomatoes pages for every
title that was previously broken. Mobile and TV Kotlin compilation and lint pass. Emulator and
device validation were waived, so the rendered result on a device is unverified.
