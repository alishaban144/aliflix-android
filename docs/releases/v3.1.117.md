# Aliflix v3.1.117

On the main screen the poster now belongs to the page instead of hovering above it: it appears only
across the hero, and scrolling down scrolls it away to reveal the dark background underneath.

## The poster was fixed behind the list

`CinematicBackdrop` was a sibling of the home `LazyColumn`, not a child of it. It filled the whole
screen and was given no scroll offset, so it never moved. That was deliberate — v3.1.115 made the
plane stationary on purpose, so a vertical scroll could not drag or stretch the artwork — but it
left two consequences on the main screen that nobody asked for:

* the sharp poster and its defocused copy were painted across the entire viewport, so the rails
  underneath the hero were never really on the Aliflix background; they sat on a fixed, blurred,
  second copy of the same picture, and the screen never became simply dark;
* the poster could not leave. Once the hero had scrolled past, the artwork was still there, which is
  why scrolling down felt like dragging a curtain instead of moving past a header.

The details screen keeps the stationary plane, because its hero is a list item too but the page is
a single title, and there is no second copy competing with the content below it.

## The plane now lives in the hero item

`CinematicBackdrop`'s three layers — the defocused copy, the fixed tint, and the sharp crop with its
alpha mask — were extracted into one `BoxScope` composable, `CinematicPlane`, and a second entry
point, `CinematicPosterPlane`, was added. It draws exactly the same layers, but sized by the caller's
box instead of a full-screen plane, and clips to that box.

Home draws `CinematicPosterPlane` inside the hero `item`, behind the `HorizontalPager`, and no longer
draws a plane behind the list at all. Three things follow, and none of them needed a scroll offset:

* the plane is bounded by the hero box, so the poster can only ever cover the hero, and
  `clipToBounds` on the plane stops the oversized, blurred ambient copy from reaching the rails;
* because the plane is a child of the hero item, it is translated by the list exactly as the hero is,
  so scrolling down carries the poster off the top and the plain `AliflixBackgroundBase` behind the
  list takes over;
* the hero item is disposed once it scrolls out, so the artwork is not even composed below that
  point.

At rest nothing changes: the hero box is `homeHeroHeight` tall, which is the height the plane was
already given, the crop and the mask are the same, and the tint is the same. The pager crossfade
between two heroes is unchanged too, and is now a crossfade of two bounded planes; the incoming one
is layered at the page offset, as before.

The status bar inset does not apply here, which is the point: the hero is the first item of a list
that starts at the very top, with the header overlaid rather than padding it, so the plane already
began at `top = 0` and no inset is needed.

## Validation

The mobile unit test suite, `lintMobileDebug`, mobile and TV Kotlin compilation and the instrumented
test sources all pass, with no new warnings. A new test asserts that the scrolling home plane is
bounded by the hero and never by the screen, so the band can no longer be widened by a caller that
measures against the viewport.

Emulator validation is waived for this release, exactly as on every release branch since v3.1.102,
so the rendered result on a device is unverified. The five pre-existing device test failures waived
by those releases are unrelated to this change, but no device run has confirmed the scroll itself.
