## Behavior

Ask Talk uses a native circular adaptation of Triangle LED Front: a luminous lavender/white edge with three feathered emitters. It becomes visible when the voice connection is ready, fades during connection loss or typing, and brightens from the actual rendered PCM envelope. Attack/release smoothing is separate from the slow moving light field. The player retains its existing soft halo, toolbar icon, bubble layout and single voice/typing control.

The player-opening Rising Ball loader preserves the reference CSS trajectory, squash/stretch and ease-in-out timing: two alternating 500 ms legs and a 1,000 ms step cycle. Only colors and the padded drawing surface are adapted. Player Talk enters along a curved path with banking, elastic settling over 620 ms and a 360 ms return. Animation respects motion preferences, lifecycle and system animator settings. Attribution is bundled in `assets/licenses/ask-motion.txt`.

## Scene data and answers

1. The native player supplies the actual pause image and available surrounding images from the selected source. Earlier selected-edition captions remain searchable locally, through the pause, including after a seek. Source credentials are never model context.
2. The Worker retrieves canonical credits and independent film or exact-episode references. These public references can include later revelations; they are background for analysis, not timestamp proof.
3. In free-tier mode, Gemini 3.8 Live compiles a focused character/causal memory through one structured tool return from earlier dialogue, images, credits and research. Character/fact references and viewing times are validated. The client receives this bounded memory rather than a raw full-episode plot paragraph. A missing provider result remains limited evidence, never a fabricated character binding.
4. Gemini Live answers the actual question in the conversation language, with the scene evidence, compiled memory and retained conversation. Typed questions and their images are delivered in the same completed turn. The model can retrieve a missing earlier passage with `scene_recall`.

Identity questions request surrounding shots and prioritize the nearby reverse shot. Decoder waiting, including waiting on a previous decode, is bounded to 3.5 seconds for identity questions and 12 seconds otherwise. Opening and simple greetings warm public references without spending a scene-inference request. A deferred opening packet can no longer satisfy an actual scene question. The native client waits for the question-directed analysis instead of silently reusing that packet. The actual-question wait allows the bounded compiler deadline to complete. Actual identity/causal questions compile focused story memory on demand; subsequent questions reuse unchanged evidence-linked facts, with old answer prose omitted. The full earlier transcript stays searchable locally. The Live wire packet merges the selected prefix and requested scene windows into one timed transcript, removes their duplicate copies and the repeated full timeline index, and keeps window timing/coverage metadata. The complete original index remains local. Rare clue terms are chosen only when they also occur in earlier selected-edition dialogue; they improve both compilation input and the existing local recall query without another model request. Free-tier extraction uses the working Gemini Live transport rather than repeatedly trying overloaded REST generation. It sends one evidence packet, accepts only the structured compile_scene_memory tool result, suppresses speech, closes the socket, and uses a 12-second deadline with a 128 KB cumulative response ceiling. There are no generation nudges or extra inference fallbacks in free-tier mode. The original REST path remains model-compatible (`low` thinking and the portable schema subset); its default extractor is Gemini 3.6 Flash, and Gemini 3.8 supports the same `low` setting. The former `minimal` setting on 3.8 and unsupported schema keywords were corrected. Application validators still enforce strict names, references, size limits and the pause boundary. Earlier identities may be corroborated by later already-viewed dialogue. The provider grammar uses only portable primitive types, properties and enums; strict application validation checks canonical names, cue/frame index ranges, real source IDs and the pause boundary. A trial adding dynamic generation-time numeric/roster bounds regressed the phone checks and was reverted. Unique surnames resolve only when one credited name matches; ambiguous names remain rejected. The structured response checks the question's identity/event assumptions before compiling facts. Evidence-linked corrections are provided explicitly; an unresolved premise must not become a confident causal fact. Credited performer names accompany validated fictional-character bindings. Up to 12 actual supporting dialogue lines (240 characters each) accompany compiler claims, letting the final answer cross-check what they establish instead of treating a current greeting as proof of an earlier theory. This is a bounded evidence addition, not another model call. If one claim fails validation, the remaining independently supported claims survive; prose associated with rejected claims is removed.

The instructions distinguish the person pictured from an offscreen speaker, separate visits, retained versus recent memory, the owner of a condition, immediate reasoning versus emotional stakes, and theory versus proof. These are behavioral constraints, not guarantees of universal correctness.

## Three Gemini projects

All three master keys are encrypted Cloudflare secrets, never APK assets or repository values. Stateless requests rotate their starting slot fairly across the three user-confirmed independent projects. A shared Durable Object coordinates admission across Worker instances: one HTTP operation in flight per project/model family, a conservative application cap of 3 requests/minute and an estimated 32,000 input tokens/minute. Token minting allows 6 starts/minute and is not charged as model input. These are Aliflix caps, not a claim about the exact Google project limits. Quota, authorization and transient provider failures can use the remaining distinct keys, at most once per key within the original request deadline. Invalid request/model parameters are not retried on another key. Cooldowns honor Retry-After and Google RetryInfo. Daily quota exhaustion blocks that project/model until the next Pacific midnight, including daylight-saving changes; short minute limits use their shorter delay. Project/model state is coordinated centrally, with hashed edge-cache identifiers as an additional fast path. Free mode removes repeated same-project backoff attempts. Provider server errors without a supplied retry delay cool the project/model for 30 seconds rather than repeatedly spending requests during overload. The HTTP admission lease ends when the upstream response arrives; it is not a lifetime lock on a direct Live conversation. Direct Live use still consumes Google project quotas. All three projects can handle independent work; no duplicate parallel answers are generated. Compiler transcript input is limited to 16,000 relevant chronological characters, public research to 6,000 characters and images to three. Matching earlier setup and nearby exchanges are retained; the larger local prefix can still be retrieved.

Structured Live analysis has its bounded text/image token estimate included in admission; the private estimate is removed before the upstream handshake. It does not require another public microphone conversation. Late client-side quota rejection can request a new constrained token on the same backend session, excluding failed project slots. At most two alternatives are tried per user turn; voice, language, expiry and research budgets are retained. The native client discards the old provider resumption handle and replays bounded conversation context without creating a new app chat. Client reports cannot globally disable projects. The server-side scene compiler also tries remaining slots for trusted post-handshake quota errors within its original 12-second deadline; trusted errors cool that project for subsequent work.

A voice session stores its successful key slot in private session state. Normal renewal stays on that project to preserve its provider resumption handle. Explicit quota recovery can switch projects, clearing that handle and replaying bounded context within the same app conversation. Existing single-key sessions default to their original project. Clients receive short-lived restricted tokens, never any master key. Embedding 2 remains the recommendation embedding model.

## Practical limits

There is no free, universal catalogue-wide same-cut scene index in this implementation. Caption coverage, cut alignment, source decoding, public cast/plot availability and model interpretation still matter. A selected caption edition is not certified alignment with every cut. Structural evidence validation cannot prove that a model interpreted every reference correctly. Cold lookups and external services can exceed a 12-second answer target. Three project quotas improve availability; they do not guarantee unlimited capacity or factual perfection.
